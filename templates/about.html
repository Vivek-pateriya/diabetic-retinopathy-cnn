RetinaCheck: Diabetic Retinopathy Classification with a Compact Convolutional Neural Network

Vivek Pateriya

Project developer · Educational machine-learning application

Abstract

RetinaCheck is an educational application developed by Vivek Pateriya to classify retinal fundus images into five diabetic-retinopathy grades. The implementation combines a compact convolutional neural network with a local browser interface. It uses consistent image preprocessing during training and prediction, a stratified validation split, and class weights to address uneven class frequencies. {% if metrics %}The recorded experiment achieved {{ '%.2f'|format(metrics.validation_accuracy * 100) }}% validation accuracy across {{ metrics.validation_images }} images.{% else %}Recorded evaluation metrics are not currently available.{% endif %} This page documents the implemented system and its limitations.

Keywords: diabetic retinopathy, image classification, convolutional neural network, TensorFlow, Flask

1. Introduction

The project explores how supervised image classification can assign a severity label to a retinal photograph. A labeled dataset supplies the examples needed to train the model. The goal is to provide an understandable workflow that connects dataset preparation, training, evaluation, and browser-based prediction.

2. Dataset and Target Classes

The application uses the Kaggle Diabetic Retinopathy 224 × 224 2019 dataset. A CSV maps each image identifier to a diagnosis label. The classifier predicts No DR (0), Mild (1), Moderate (2), Severe (3), or Proliferative DR (4). Dataset ownership and usage terms remain with its provider.

3. Methodology

3.1 Data preparation

The loader matches CSV identifiers to images and rejects missing images, duplicate identifiers, or invalid labels. A deterministic split reserves approximately 20% of each class for validation. Class weights compensate for unequal training class counts without duplicating validation images.

3.2 Image preprocessing

The shared decoder converts an image to three RGB channels, resizes it to 160 × 160 pixels, and scales pixel values to the range 0–1. Both training and prediction use this transformation. Random horizontal flips and small rotations apply during training.

3.3 Network architecture

Three convolution layers use 12, 24, and 48 filters with stride 2. Global average pooling reduces the feature maps to a compact representation. A dense layer with 64 units and dropout of 0.25 precedes a five-unit softmax output. The model trains with Adam at a learning rate of 0.0003 and sparse categorical cross-entropy loss.

3.4 Training and evaluation

The default batch size is two images. Early stopping monitors validation loss with patience of five epochs and restores the best weights. Training saves the selected model, the image split, validation accuracy, and a confusion matrix. Repeated use of the same validation split for model selection limits its independence as a performance estimate.

5. Application Implementation

The Flask backend accepts PNG and JPEG uploads up to 10 MB, verifies image readability, and loads the saved model to generate predictions. Temporary uploaded files are removed after processing. The frontend displays an image preview, the predicted grade, and all five model probabilities. A light/dark theme switch remembers the user's preference in the browser.

6. Limitations and Future Work

The model has no external clinical validation. Softmax scores do not represent calibrated diagnostic confidence, and the classifier does not verify that an uploaded image is a retinal photograph. Future experiments could assess a separate test dataset, calibration, per-class recall, transfer learning, and robustness to image quality.
